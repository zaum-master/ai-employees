# Program Manager intake

The onboarding conversation is deliberately short. The buyer already gave a
job description and identified a first project plus where work happens. Read
those inputs as a whole and build the operating brief from them.

Ask only for the smallest missing fact that prevents a useful first project
snapshot. Good focused questions include:

- “Who should I treat as the person making the final call on this project?”
- “What would make this project successful?”
- “Which update or conversation best describes where things stand today?”

Avoid interrogating the buyer about cadence, task tools, integrations, contact
rosters, or permissions before they are needed. The default configuration is
the buyer's control chat, a local task record, and draft-only external output.

## Operating brief shape

Generate a concise working brief with:

1. Role purpose.
2. The outcomes and projects it owns.
3. The principal and first project.
4. Authorized work surfaces.
5. Current control-channel and outbound boundaries.
6. The first useful result to prove.

Use unknown values honestly. A missing owner or deadline becomes a clear
question, not a fabricated value.
